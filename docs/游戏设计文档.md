# 《六点下班》游戏设计文档

> 更新：2026-09-15。基于当前工作区代码核对，包含未提交改动；不是多人联机或完整对局的验收报告。
> 当前阶段：Godot 4.7 / GDScript 可测试原型，正在完善测试入口和办公室氛围。
> **已实现**指代码已有逻辑；**待验证**指需要实际试玩；**规划**尚未进入游戏。

关联：[画风与资产](画风与资产方案.md) · [办公室扩建与沉浸设计](办公室扩建与沉浸设计.md) · [早期方案归档](游戏设计文档-早期方案归档.md)。旧稿保留设计沿革，不再作为当前功能清单。

## 1. 定位与核心循环

1 个老板对 4 个员工的 2D 非对称办公室对战。员工想在六点前完成工作并打卡，老板用监督、约谈和会议拖延下班。职场黑色幽默与下班前的压迫感并存。

员工选择：继续工作、原地摸鱼、外出续命，或冒险救同事。老板选择：守一个人、巡逻抓包，或消耗技能打断员工。场景氛围服务这些判断，不遮住交互和路线。

员工：坐下工作 → 精力下降 → 摸鱼/咖啡/厕所恢复 → 继续工作 → 工时归零 → 自动去打卡 → 个人离场。

## 2. 实现范围

| 系统 | 当前状态 |
|---|---|
| 身份 | 小马、兔子、牛、鹈鹕四个员工位置与老虎老板；员工外观无专属数值差异 |
| 测试入口 | 打卡上班先进入身份核验；确认后开本机测试房，空位补 Bot；`--test` 也先进入身份页 |

| 老板 | 监督、约谈、点名开会、KPI、老虎冲刺 |
| 地图 | 单层办公室、家具碰撞、7 道可操作门、房间视野遮罩、分区镜头 |

## 3. 资源与状态

| 项目 | 当前数值与行为 |
|---|---|
| 初始工时 / 精力 | 100 / 100；精力上限 100 |
| 工作 | 有精力时工时每秒 -1.15，精力每秒 -2 |
| 空精力工作 | 工时每秒 -0.05；不是完全停止 |
| 工位摸鱼 | 精力每秒 +2，工时不减少 |
| 喝咖啡 | 精力每秒 +6；离开时获得 20 秒工作效率 ×1.2 |
| 厕所 | 精力每秒 +7，不提供工作加速 |
| 走动 | 不自然恢复精力，不减少工时 |
| 开会 | 持续 9 秒，精力每秒 -0.4，不减少工时 |
| 约谈 | 暂停工作和恢复，完成复盘才结算加时 |
| 工时归零 | 自动进入去打卡状态，按路径走向最近打卡机，距离 48 内离场 |

工时是剩余工作量，不是现实秒数。理想连续工作约需 87 秒，但初始精力只能支持约 50 秒；这个计算未计监督、跑图与咖啡增益。

当前咖啡提前离开也给增益，并非旧稿“喝满才给”。工时归零后由代码接管移动，不要求玩家手动走去打卡。这两点按现状记录，不在文档更新时暗改规则。

## 4. 老板与救援

| 行为 | 当前实现 |
|---|---|
| 监督 | 靠近员工或工位监督点 78 单位内；老虎将正常工作效率降至 30% |
| 自动抓摸鱼 | 被监督的工位摸鱼持续 1.2 秒进入约谈 |
| E 约谈 | 距离 70 内，对摸鱼、咖啡、厕所或正在救援的员工有效 |
| 复盘 | 老板与被约谈者处于相同视野分区时约 5 秒完成，否则约 10 秒 |
| 惩罚 | 首次工时 +12；12 秒连谈窗口内再次惩罚 +18；起身锁定 3 秒 |
| E 捞人 | 初始距离 72 内，连续救援 1.2 秒；移动、超距、老板回到视野等会中断 |
| 救出 | 被救者不结算本次加时；两人获得 1.6 秒、×1.28 移速 |
| Q 开会 | 420 范围内自动选择可见的最近有效员工，墙体射线阻挡；老虎冷却 22 秒 |
| R KPI | 开局 40 秒解锁，冷却 75 秒，未离场员工工时 +10 |
| Shift 冲刺 | 冷却 12 秒，持续 0.28 秒，速度 420 |

员工速度 168；老虎正常速度 182×1.15。距离和速度使用游戏世界单位。

“看着复盘”基于房间/视野分区，不等同于精确视线，不要求朝向。老板在场不能救出同事；救援者只有进入约谈距离时才会因硬救被约谈，不能写成整间屋必抓。

### 已知规则边界，待修正或明确

- 去打卡者不会成为约谈/会议目标；但当前 KPI 仍给未离场的去打卡者加工时，且不会使其退出去打卡状态。建议后续排除该状态，尚未改代码。
- 当前监督和手动约谈没有与开会相同的墙体射线检查。扩建加入隔断前需统一规则，避免隔墙干预。
- 会议目前可选择约谈中或会议中的员工；是否允许重复打断需明确，不能宣称已有免疫。

## 5. 当前地图与信息差

边界 2560×1520；北侧为厕所、储物、茶水、休息，中间为高 220 的横走廊，南侧为门厅、工位和会议区。

实际工位区域为 `Rect2(520,780,800,456)`，四个工作位置分布在两张共享桌旁。两台打卡机都在门厅，并未分散在两条出口路线；咖啡、厕所各有两个恢复位置。

员工可以关门，双方开门约需 1.65 秒；门状态由服务端同步。视野按房间划分，走廊另分左右；不是连续遮挡视野。家具碰撞不自动意味着能阻挡所有观察和技能。

老板界面应保留工位粗状态，避免公开所有员工精确进度。当前网络会向客户端同步资源数值，因此这是界面信息差，还不能视为网络层防窥探。

扩建动线、空间尺度、沉浸系统和验收见[办公室扩建与沉浸设计](办公室扩建与沉浸设计.md)，均属于下一版规划。

## 6. 流程与结算

1. 输入工牌名，核验员工或老板身份。
2. 本机测试补齐四个 Bot；联机使用已有房间/连接流程。
3. 员工出生在工位，老板出生在走廊；计时开始。
4. 工作与恢复循环；归零者自动打卡并离场。
5. 时间耗尽或四位员工全部离场，结算个人与老板结果。
6. 返回大厅，可重新选身份测试。

| 下班人数 | 老板结果 | 员工结果 |
|---|---|---|
| 0–2 | 胜 | 每个人按自己是否离场判断 |
| 3 | 平 | 已离场三人仍为个人胜 |
| 4 | 负 | 四人均个人胜 |

UI 使用“工时、精力、续命、约谈、复盘、捞人、已下班”等职场用语。重要提示必须清楚，故障文字不能影响操作判断。

## 7. 操作与启动

| 身份 | 操作 |
|---|---|
| 员工 | WASD 移动；E 交互/救人/门；F 在工位切换摸鱼 |
| 老板 | WASD 移动；E 约谈/门；Q 开会；R KPI；Shift 冲刺 |

- `play.bat` 或 `godot --path . -- --test`：身份选择后快速测试，不连 Go。
- `server.bat` 或 `go run ./cmd/clockout-server`：Go 权威服，端口 27111。
- 客户端「接入监控」连 `ws://IP:27111`，开设房间或输入 4 位房间码。对局中途不可加入。
- `Rules.gd` 中 19107 为旧常量；联机端口以 Go / `Net.gd` 的 27111 为准。

## 8. 技术边界

入口为 `src/game/Game.tscn`；自动加载 `Rules`、`Net`、`Match`。`Game.gd` 管界面/镜头，本地测试时 `Match.gd` 管对局；联机时权威在 `server/`（Go），Godot 只插值和画。`Actor.gd` 管角色表现，`OfficeMap.gd` 管布局/装饰/寻路。预览 HTML 是资产浏览工具，不是游戏客户端。

联机：Go 大厅多房间，角色快照约 15 Hz，客户端插值。房主可开局/重置；对局中断线转为 Bot；空房销毁。本机测试不连服务器。途中加入补世界仍未做。

员工 Bot 按精力阈值工作、恢复和救援；老板按固定点巡逻。寻路依赖门口坐标，老板追逐还有直线走向目标的分支。扩建不能只改墙和图片。

现有代码有视觉氛围，未见完整音频播放系统；空间环境音、脚步与设备声列为待实现。

## 9. 后续范围

1. 近期：双侧测试、门口与自动打卡路径、交互提示、上述规则边界。
2. 地图版：扩大工位活动空间，做双路线，统一房间/门/交互点数据，再放置资产。
3. 沉浸版：分区声音、设备反馈、时间灯光、空工位变化、降低闪烁/抖动的选项。
4. 后续探索：保温杯/装忙/尿遁员工技能三选一，鳄鱼与猫头鹰，外观与经验。数值未锁定，当前没有经验奖励实现。

扩建保持四员工、一老板、两咖啡位、两厕位和两打卡机，不同时修改技能冷却、恢复容量和胜负规则，以便辨别地图变化的影响。

## 10. 验收口径（未宣称已通过）

- 两阵营均能进入、结束、再次开局；单人测试共 5 角色、4 Bot。
- 摸鱼只回精力；约谈能完成也能救出，会议不能捞人解除。
- 门、占位、KPI、会议、打卡在各客户端一致。
- 任一座位可到恢复点和打卡机；关门、绕桌、断线不导致整局卡死。
- 用正常 10 分钟局评估平衡，短局检查流程；记录下班人数、被抓次数、恢复选择与无效移动时间。
