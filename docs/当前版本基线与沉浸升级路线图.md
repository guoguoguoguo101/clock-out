# 《六点下班》当前版本基线与沉浸升级路线图

> 更新：2026-09-16。此文以当前 `src/` 与 `server/` 代码为准，作为后续玩法、美术、关卡和数值工作的共同基线。旧的《游戏设计文档》保留为早期方向记录，其中部分数值已经过时。

## 一句话定位

**一局 8–10 分钟的“办公室生存协作”非对称游戏。**六名动物员工在真实而逐步失常的互联网办公室中完成交付、管理精力、互相救援并打卡；虎老板通过巡视、短扑、周报与事故，把“按时下班”变成一连串有风险的选择。

恐怖感不应来自常驻红滤镜或扭曲文字，而应来自熟悉办公物件开始不对劲：同一封离职邮件反复出现、空工位显示在职、监控里多了一名员工、会议室的门在没有人时自己合上。

## 当前可运行内容（代码基线）

| 模块 | 当前实现 |
| --- | --- |
| 对局 | Godot 4.7 俯视角；标准局 `600s`，短局 `180s`；办公室地图 `2560×1520`。本地 Godot 房与 Go 权威服务端两种路径。 |
| 阵营 | 固定 1 名虎老板对 4 名员工：小马、鹈鹕、袋鼠、小狗。兔子与牛保留为未启用的历史资产，不进入运行时槽位。 |

| 员工机动/救援 | 全员冲刺；鹈鹕飞行和搬运，袋鼠电瓶车，小狗召唤 3 名“兄弟”挡扑，员工可救援约谈/会议中的队友；股票桌提供风险收益。 |
| 老板压制 | 近距离巡视降低工作效率；短扑命中进入约谈；周报投掷减速；3 层势力可把约谈对象送会议室 30 秒；KPI 与线上事故可损失任务或制造全局压力。 |

### 当前资产盘点

`assets/game` 约 **90.9 MB / 766 个文件**：角色 605、道具 98、UI 49、特效 14；其中角色已覆盖虎、马、兔、牛、鹈鹕、袋鼠、狗及围巾层。`assets/concept` 约 **27.7 MB / 78 个文件**，主要是概念素材。

结论不是“素材数量不够”，而是**大部分资产还没有被绑定为可读的对局状态**。已经有角色行走、坐姿、骑行、飞行、周报碎裂等表现，但工作、被扑、约谈、救援、故障、房间异常之间仍缺少连续的视觉因果。

## 为什么现在会觉得快、薄、没有被打到的感觉

### 1. 核心循环被一次按键自动完成

当前一格精力换一单 10 秒自动工作：5 单的纯工作时间仅 50 秒。即使只依靠摸鱼补齐 5 格，理论最短也大约是 **95 秒 + 跑图**；咖啡、零食、外卖与股票还会继续压缩时长。

玩家在最关键的“交付”阶段只是在等待条走完，因此并没有形成“我凭操作把风险中的工作保住了”的记忆。离开工位又会丢掉本单全部进度，会把决策变成二元的“坐着等/被迫重来”。

### 2. 老板命中是硬切状态，不是一次事件

短扑仅 0.32 秒、命中恢复仅 0.4 秒；被命中的员工马上进入 `TALK`，速度归零，持续 10 秒。没有预警、冲击、拖拽、挣扎、同伴介入窗口或脱身后的余波，玩家自然会觉得“人站在原地”。会议室更是直接把人传送并锁 30 秒。

这让虎老板的强度来自剥夺控制，而不是读位、施压和反制；员工的救援也只剩 2.5 秒读条，缺少戏剧性。

### 3. 系统很多，但没有统一到同一张压力表

飞行、骑车、兄弟、搬运、股票、事故、外卖、停电都各自成立，却主要改变移动或直接给资源。它们没有共同影响“交付风险、老板压力、团队路线”中的至少两项，因而像功能清单，而不是会彼此咬合的角色策略。

### 4. 办公室尚未成为会记住玩家的场所

目前办公室有点位和遮挡，缺少可持续变化：哪台工位正在赶工、哪台打印机在吐异常文件、哪个会议室被审查、哪里发生过事故、老板刚去过哪里，通常只在短暂 UI 或文字里出现。无声条件下更需要这些环境信号。

## 目标体验与节奏

建议先锁定下面的体验目标，再调具体数值。

| 阶段 | 时间 | 员工感受 | 老板感受 | 环境变化 |
| --- | ---: | --- | --- | --- |
| 17:50–17:53 入座 | 0–3 分钟 | 认路线、拿第一份交付、判断谁擅长什么 | 标记高价值工位、试探冲刺与门 | 正常冷白灯；屏幕偶尔跳异常通知。 |
| 17:53–17:58 压力 | 3–8 分钟 | 在做任务、补精力、救人之间做取舍 | 用巡视与小扑迫使员工离席，累积压迫资源 | 灯闪、打印机堆积、会议室预约板异常、走廊封控。 |
| 17:58–18:00 下班潮 | 8–10 分钟 | 带着已完成交付穿越最后路线并打卡 | 抓关键目标、封路线、用一次大招制造最后决策 | 门禁切红、监控轮播“第 5 位员工”、前台显示下班倒计时。 |

**标准局成功打卡的中位时间应在 5–7 分钟，而不是 1–2 分钟。**短局可以保留给测试，但不应拿它代表正式体验。

## 先做的玩法改造（按收益排序）

### P0：让“做工作”和“被抓”都能操作

1. **把一单工作拆成 3 个小阶段，而不是把 10 秒简单拉长。**
   - `准备`：选择一份任务（日报/复盘/需求/线上问题），看到风险标签；
   - `执行`：12–16 秒低频小操作，例如拖拽优先级、在变动的报表里找异常、短节奏确认；
   - `提交`：2 秒提交窗，老板近时可选择“硬提、暂存、伪装成摸鱼”。
   - 被迫离席时保留 70–80% 的阶段进度，并生成一层“返工/风险”，而非归零。这样有痛感但不挫败。

2. **把精力从“开工门票”改为持续抉择。**
   - 低成本首版：初始给 1 格；任务增至 6–7 单，每阶段 12–14 秒；补给点有库存、冷却与被巡视风险。
   - 完整版：4 格仍是外显，但每格是一段 25–35 秒的“专注窗口”，工作中逐步消耗；精力见底时可以慢做、冒险摸鱼、向队友借助或停下补给。
   - 外卖、股票和事故奖励只提供“选择权”或短时窗口，不要直接等价于多单免费工作。

3. **重做虎老板命中链：预警 → 冲击 → 可反制的审查。**
   - 短扑前 0.35 秒显示地面爪痕/影子与朝向，给员工一次冲刺或转门的读位机会；扑空保留明显 1.0–1.3 秒破绽。
   - 命中后先有 0.25 秒击退、文件散落、角色失衡，再由虎老板把员工拖到最近“审查区” 1.5–2 秒；不要瞬间原地冻结。
   - 审查维持 4–6 秒：被抓者可做一个低频“对齐/甩锅/摸鱼记录”选择；队友可从不同方向打断、递交伪证或搬走。失败产生返工/警告层，成功逃脱则让老板失去压迫资源。
   - 会议室应是老板攒到资源后的强力**地图事件**，先显示预约/锁门/投影异常，再把人带入；30 秒纯锁定改为 10–15 秒、可被两人协作提前解锁。

4. **为所有结果增加“开始—进行—结束”三拍。**
   - 命中：预警环 → 爪击定格 2–3 帧/屏幕轻推 → 拖痕、纸屑、员工受惊动作；
   - 救援：同伴靠近时出现两人的牵引线/进度拼接，成功后惯性冲出半步和 1 秒短暂护盾；
   - 工作：坐下亮屏、进度时键盘/屏幕/打印机同步，提交时工位指示灯由黄变绿；
   - 事故：先有异常闪烁，再有污染范围与终端交互，处理成功/失败必须永久改变一个房间的状态。

### P1：把员工与老板做成团队博弈，而不是移动技能展示

| 角色方向 | 现有基础 | 建议补强 |
| --- | --- | --- |
| 鹈鹕 | 飞行、搬运 | 作为“转移/撤离”专家：能跨门救人，但飞行落点会留下被监控标记。 |
| 袋鼠 | 电瓶车 | 作为“跑图/物流”专家：带外卖、搬运文件更快；骑车噪眼大，容易被老板锁定。 |
| 小狗 | 3 名兄弟挡扑 | 作为“护卫/信息”专家：兄弟能蹲守一处门口或护送，但无法同时全图保护。 |
| 小马 | 当前是基础员工 | 作为“稳定提交”专家：保留任务阶段进度、降低返工风险。 |
| 鹈鹕、袋鼠、小狗 | 飞行/搬运、骑车、兄弟挡扑 | 分别承担转移撤离、物流跑图、护卫信息；每项能力都要同时影响任务与路线/信息。 |
| 虎老板 | 巡视、短扑、周报、会议、KPI、事故 | 增加唯一资源“管理压迫”：盯住、命中、封控产生；KPI/会议/事故都花它。避免每个技能独立冷却、随时间白送。 |

每个技能至少回答两个问题：它怎样改变**任务进度**？怎样改变**路线/信息**？如果只改变移速，优先降级为基础移动能力。

### P2：让地图在无声状态下讲恐怖故事

按“正常 → 有问题 → 失常”做可替换状态，不需要整张图都上恐怖滤镜。

| 区域 | 正常 | 有问题 | 失常（后段/事件） |
| --- | --- | --- | --- |
| 工位区 | 屏幕、键盘、待办便签 | 打印机持续吐同一页、某屏幕显示未读离职邮件 | 某空工位亮起并显示“员工 05：在岗”；椅子缓慢转向镜头。 |
| 茶水间 | 咖啡蒸汽、零食缺货 | 饮水机水位反向、冰箱贴纸变多 | 监控小屏闪过不属于本局的角色。 |
| 卫生间 | 门牌、镜面、流水痕 | 镜中角色延迟半拍 | 隔间门轻晃，镜子里有第 5 位员工。 |
| 会议室 | 预约板、投影、椅子 | 预约自动改成员工名 | 红色仅局部用于“正在审查”；门禁锁、投影显示异常考勤。 |
| 走廊/前台 | 指示牌、考勤机、快递 | 门禁闪黄、外卖袋堆积 | 走廊监控轮播、地毯上留下拖拽的纸张路径。 |

## 美术、动画与特效制作清单

优先做“状态资产”，不是再补一批独立插画。

| 优先级 | 资产/动画 | 最小交付 |
| --- | --- | --- |
| P0 | 所有员工受击、失衡、被拖、挣扎、获救、提交成功 | 每角色 6 组短动画；先共用骨架/方向与调色，后做个性差异。 |
| P0 | 虎老板短扑与审查 | 预备、冲刺、命中、扑空、拖行、指令 6 段；每段配地面提示与纸屑/爪痕。 |
| P0 | 工作站三态 | 每类工位都要有空闲/工作/异常：屏幕、键盘、指示灯、文件堆四件套。 |
| P1 | 事件套件 | 停电、事故、外卖、内网各 1 套地图覆盖物 + 1 套 UI + 1 个角色反应。 |
| P1 | 恐怖办公小物 | 8–12 张公告/警告贴纸、6 个监控内容、地毯/走廊/茶水间/卫生间纹理，按房间状态替换。 |
| P2 | 员工个性动作 | 例如小狗守门、鹈鹕转移文件、袋鼠配送、小马整理文件；不要优先做纯待机表演。 |

表现原则：冷灰蓝作为日常，暖黄只代表仍可工作的工位，警告红只指向**具体且可交互的威胁**。文字保持清晰，恐怖放到第二眼才发现的环境细节中。

实现上优先用 Godot 的 `AnimationPlayer`、补间、粒子、角色偏移和叠层贴图完成触感；AI 生图适合补“公告、监控、纹理、可拆分角色姿势”，不适合直接生成全部特效序列。

## 当前技术与数据架构

```text
Game.tscn / Game.gd
├─ Match.gd             对局状态、技能结算、随机事件、RPC
├─ Actor.gd             移动、员工/老板状态、工作、精力、角色技能、视觉（当前过于集中）
├─ OfficeMap.gd         房间、工位、门、视线、地图交互点
├─ Rules.gd             GDScript 数值与角色/资源路径
├─ CharKit / FX / UI    角色帧、飞行/周报/兄弟等表现与 HUD
└─ Net.gd               本地/ENet/Go 服务端路径

server/（Go）
├─ hub / lobby / protocol  WebSocket 房间与同步
└─ sim                    服务端模拟、地图、AI、规则、测试
```

### 架构风险：两套规则已经漂移

Go 服务端的槽位现已同步为 1v4（小马、鹈鹕、袋鼠、小狗），但仍保留旧的 0–100 连续精力与旧模拟；`src/game/Rules.gd` 已是 4 格精力、任务制，且小狗能力没有完整落在 Go 模拟。因此当前本地 Godot 路径和 Go 联机路径**不应被视为同一套平衡**。这不是小数值差异，而是玩法版本分叉。

后续开发必须先选一个权威规则源：

1. 把角色、任务、精力、事件、技能的静态数据移到 `data/*.tres` 或 JSON；
2. Godot 与 Go 均从同一份导出的数据读取，或明确只保留其中一个权威模拟；
3. 将 `Actor.gd` 拆为 `Movement`、`WorkState`、`CaptureState`、`CharacterAbility`、`ActorVisual`；
4. 给每局记录本地 JSON 事件：任务开始/提交/中断、精力来源、短扑命中/扑空、审查/救援、事件结果与打卡时间。

这些日志是以后调“快不快、老板强不强”的依据，而不是只靠体感改常量。

## 验收指标与执行顺序

### 第一轮（3–5 个开发日）

- 给工作、短扑、审查、救援做完整三拍反馈；
- 任务改成可中断但不会清零的阶段式进度；
- 做 1 个可重复的办公室异常链（工位屏幕 → 监控 → 会议室）；
- 记录一局内上述关键事件。

验收：玩家在不看说明的情况下，能看懂“谁在赶工、谁被审查、哪里能救、老板为什么攒到会议”；被扑后 1 秒内仍有自己的决策，不是只能等。

### 第二轮（1–2 周）

- 收束 6 个员工的职责与虎老板的管理压迫资源；
- 让事故/停电/外卖真实改变路线和任务，而非只弹提示；
- 将正式局的中位打卡时间校到 5–7 分钟，并检查双方胜率、救援率和扑空率。

### 第三轮（持续）

- 将每个区域补齐正常/异常/失常三态；
- 用数据资产表管理每张贴纸、监控内容、纹理、角色动作的用途、尺寸、状态和来源；
- 每次新增能力都做一次“它是否同时影响任务、路线、信息中的两项”的评审。

## 后续最适合使用的 Codex 能力

| 能力 | 适用任务 | 建议使用时机 |
| --- | --- | --- |
| `imagegen`（当前已可用） | 按现有动物角色生成受击/拖拽姿势参考，制作公告、监控屏、旧化纹理与房间状态资产 | 先定状态清单与尺寸，再一批批生成，避免无用途素材堆积。 |
| `computer-use` | 实际运行 Godot，按剧本试玩员工/老板，捕捉“读不懂、太快、被控太久”的画面证据 | 第一轮反馈完成后，每次调平衡都跑 10 局固定脚本。 |
| `visualize` | 做可交互的对局时长、精力来源、任务阶段、命中/救援概率平衡器 | 改数值前先把目标曲线可视化，尤其是 5–7 分钟打卡目标。 |
| `skill-creator` | 做一个项目专属 `godot-playtest` 技能：启动测试、跑规则一致性检查、导出对局日志、更新资产表 | 玩法进入反复迭代前创建，避免每次靠口头流程。 |

目前不必为了 Godot 再安装泛用技能；更有价值的是根据这个项目创建一条固定的“试玩—记录—平衡—资产验收”工作流。Codex 的技能适合把这类可重复的指令和资源固化下来，官方说明见 [OpenAI 开发者文档](https://developers.openai.com/api/docs/guides/latest-model)。
